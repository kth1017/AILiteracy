# AI 학습 출발점

2026년 11월 21일 워밍업에서 사용자가 직접 설명한 내용을 기록한다. 지금까지 드러난 관심은 **생성형 AI 애플리케이션이 문서를 찾아 답하고, 외부 도구를 연결해 일을 수행하는 과정**에 모여 있다. 아래 교정 내용은 이번에 제시한 피드백이며, 새 사례에 적용해 이해를 확인하는 단계는 아직 진행하지 않았다.

## 사용자가 설명한 여섯 개념

| 개념 | 처음 설명에서 짚은 부분 | 다음 설명에서 보완할 부분 |
| --- | --- | --- |
| 에이전트 | AI가 대화를 넘어 실제 업무를 수행할 수 있다고 설명했다. | 채팅은 인터페이스이고 에이전트는 작업 방식을 가리킨다. LLM 기반 에이전트에서는 모델이 목표와 중간 결과를 보고 다음 행동을 고른다. 외부 작업은 연결된 도구가 실행한다. [에이전트와 워크플로](https://www.anthropic.com/engineering/building-effective-agents) |
| AGI | 여러 종류의 인간 업무에 걸친 능력에 주목했다. | 범용 인공지능은 다양한 지적 과제를 배우고 해결하는 능력에 관한 개념이다. 에이전트 다음에 오는 특정 LLM 버전으로 정해져 있지 않다. 공통으로 합의된 달성 기준도 없다. [Google DeepMind의 AGI 연구](https://deepmind.google/research/publications/66938/) |
| LLM | GPT, Gemini, Claude를 예로 들어 AI 제품이 모델을 활용한다는 점을 짚었다. | LLM의 L은 Language다. 대규모 언어 모델은 언어의 패턴을 학습해 입력에 따라 출력을 계산한다. 중앙 집중형 서비스는 배포 방식 중 하나이고, 기기에서 실행하는 모델도 있다. [언어 모델 기초](https://developers.google.com/machine-learning/crash-course/llm) · [Gemma 모델](https://ai.google.dev/gemma/docs) |
| MCP | 서버의 기능을 여러 AI 앱에서 공통 방식으로 연결할 수 있다는 목적을 짚었다. | MCP 자체가 클라이언트–서버 프로토콜이다. 서버의 도구는 기존 API를 호출할 수 있다. 스킬은 절차를 담고, 도구는 실행할 기능을 제공한다. 스킬을 제공하는 확장도 있다. 환불 처리 같은 업무 로직, 인증, 배포·운영은 해당 서비스의 구현과 운영 주체가 담당한다. [MCP 아키텍처](https://modelcontextprotocol.io/docs/learn/architecture) · [Skills 확장](https://skills.extensions.modelcontextprotocol.io/) |
| RAG | 관련 문서를 찾아 그 결과를 문맥에 넣고 답변을 생성하는 순서를 설명했다. | 검색은 질문에 맞는 외부 근거를 공급하기 위한 단계다. 기본 LLM이 매번 인터넷 전체를 탐색한다는 전제는 수정한다. 런북은 가능한 자료원 중 하나다. [검색 증강 생성](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html) |
| 임베딩 | 문서를 벡터화해 저장하고 검색에 활용하는 사례를 설명했다. | 임베딩은 대상의 특성을 숫자 벡터로 표현한 것이다. 벡터 검색에서는 질문도 비교 가능한 벡터로 바꾼다. 추천에 상품 임베딩을 쓰는 등 쓰임은 더 넓고, RAG의 검색에는 키워드 검색도 쓸 수 있다. [임베딩 기초](https://developers.google.com/machine-learning/crash-course/embeddings) |

## 우선 확인할 개념

아래 항목은 이번 설명만으로 이해 범위를 확인하기 어려웠던 개념들이다.

1. **머신러닝·딥러닝과 문제 유형**. 머신러닝은 데이터에서 패턴을 학습하는 방법이고, 딥러닝은 여러 층의 신경망을 쓰는 머신러닝이다. 예측·분류·추천·생성이 각각 어떤 문제를 푸는지 구분한다.
2. **학습·추론·미세조정**. 학습은 모델 내부의 수치인 가중치를 조정한다. 추론은 학습한 모델로 새 입력을 처리한다. 미세조정은 이미 학습한 모델을 추가 데이터로 더 학습시키는 방법이다.
3. **토큰·컨텍스트·메모리**. 토큰은 텍스트를 처리하는 단위다. 컨텍스트는 이번 호출에 제공된 정보이고, 앱의 메모리는 나중에도 쓸 정보를 보관하고 필요할 때 다시 제공하는 기능이다.
4. **도구 호출·워크플로**. 도구 호출에서는 모델이 기능과 인자를 제안하고 실행 환경이 작업을 수행해 결과를 돌려준다. 워크플로는 개발자가 처리 순서와 분기를 정해 둔 절차다.
5. **평가·일반화**. 평가는 대표 사례와 판정 기준으로 시스템의 성능을 확인하는 일이다. 일반화는 학습 중 보지 않은 사례에서도 배운 패턴이 통하는 성질이다.
6. **권한과 운영 관측**. 권한은 누가 어느 자료를 읽고 어떤 작업을 수행할 수 있는지 정한다. 로그와 지표를 보면 실제로 무엇을 호출했고 어디서 실패했는지 확인할 수 있다.

실무 이해를 다음에 확인할 사례는 사내 환불 도우미다. 최신 규정을 찾아 설명하는 경로와 결제 시스템에서 실제로 환불하는 경로를 따라가며, 각 단계에서 쓰는 정보, 실행 주체, 성공 여부를 확인할 근거를 설명해 본다.
