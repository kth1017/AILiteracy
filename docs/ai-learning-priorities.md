# 개발에서 쓰이는 AI 개념의 학습 우선순위

앞선 개념이 다음 주제를 이해하는 데 얼마나 필요한지, 개발자와 실제 설계나 검증 방법을 논의할 때 얼마나 유용한지를 기준으로 순서를 정했다. 개발자가 AI를 활용해 소프트웨어를 만드는 일과 제품에 AI 기능을 넣는 일을 모두 다룬다.

| 우선순위 | 배울 개념 | 이해를 확인하는 실무 질문 |
| --- | --- | --- |
| 1 | **AI 모델, 학습, 추론**. 데이터에서 패턴을 배우는 과정과 학습한 모델로 새 입력에 답하는 과정 | 챗봇이 방금 알려 준 내 이름을 다음 문장에서 썼다. 이것만으로 모델이 새로 학습했다고 말할 수 있을까? |
| 2 | **문제에 맞는 기술 선택**. 규칙, 분류, 예측, 추천, 검색, 생성. [Google 머신러닝 과정](https://developers.google.com/machine-learning/crash-course/) | 고객 문의를 담당 팀에 보내는 일, 환불 규정을 찾는 일, 답변 초안을 쓰는 일에는 각각 어떤 방식이 어울릴까? |
| 3 | **데이터와 평가**. 좋은 결과의 기준, 대표 사례와 예외, 처음 보는 데이터에서의 성능. [Google의 데이터 분할·평가 설명](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets) | 문의의 95%가 결제 관련이라면 모든 문의를 결제팀에 보내도 정확도는 95%다. 이 기능을 출시해도 될지 무엇으로 판단할까? |
| 4 | **대규모 언어 모델(LLM), 토큰, 프롬프트, 문맥**. 모델이 글을 생성하는 원리와 답변 시점에 실제로 볼 수 있는 정보. [Google의 언어 모델 기초](https://developers.google.com/machine-learning/crash-course/) | 같은 질문에 파일을 첨부하면 왜 답이 달라질까? 그럴듯하지만 틀린 설명은 어떻게 확인할까? |
| 5 | **AI를 활용한 소프트웨어 개발**. 코드 설명, 수정 제안, 변경 내역 검토, 테스트. [GitHub의 AI 개발 워크플로](https://docs.github.com/en/copilot/get-started/about-github-copilot) | AI가 “버그를 고쳤다”고 보고했다. 어떤 변경을 읽고 어떤 테스트를 해 봐야 원래 문제가 해결됐다고 판단할까? |
| 6 | **모델 API와 도구 호출**. 앱이 모델에 요청을 보내고, 정해진 형식으로 결과를 받아 외부 기능과 연결하는 방법. [Anthropic의 도구 호출 설명](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works) | 챗봇이 “예약했습니다”라고 답할 때, 실제 예약은 어느 프로그램이 처리하고 성공 여부는 어디서 확인할까? |
| 7 | **검색, 임베딩, 검색 증강 생성(RAG)**. 질문과 관련 있는 자료를 찾아 모델에 답변의 근거로 제공하는 구조. [Google Cloud의 RAG 아키텍처](https://docs.cloud.google.com/architecture/rag-reference-architectures) | 사내 챗봇이 틀렸을 때, 올바른 문서를 못 찾은 경우와 찾아 놓고 잘못 답한 경우를 어떻게 구분할까? |
| 8 | **워크플로와 에이전트**. 프로그램이 단계를 미리 정하는 방식과 모델이 상황에 따라 다음 행동을 고르는 방식. [Anthropic의 워크플로·에이전트 설명](https://www.anthropic.com/engineering/building-effective-agents) | 환불 처리에서 어느 단계의 순서를 고정하고, 어느 판단을 모델에 맡기며, 어디에 사람의 승인을 둘까? |
| 9 | **서비스 운영과 아키텍처**. 접근 권한, 개인정보, 비용, 응답 시간, 기록, 장애 대응. [Google Cloud의 AI 시스템 운영 지침](https://docs.cloud.google.com/architecture/framework/perspectives/ai-ml/reliability) | 내 문서 요약은 잘되는데 전 직원에게 공개하려면 무엇이 달라질까? 다른 팀의 문서 노출을 어디서 막고, 느린 답변의 원인은 어떻게 찾을까? |
| 10 | **모델 내부 구조와 맞춤 학습**. 신경망, 트랜스포머, 사전학습, 파인튜닝 | 매일 바뀌는 규정을 반영하는 문제와 수만 건의 문의에 일관된 분류 기준을 적용하는 문제에서 각각 무엇을 바꾸고 어떻게 효과를 검증할까? |

1~4번은 공통 기초다. 5번부터는 관심 있는 실제 사례에 맞춰 순서를 조정할 수 있다. 예를 들어 나만의 문서 비서를 만들고 싶다면 6번의 API와 7번의 검색을 연결해서 배우고, 9번에서 다루는 문서 접근 권한도 이때 함께 살펴본다.
